# Growth-induced metabolic decoupling in tumors — figure code

Code that reproduces every data figure in

> D. Levy, *A Non-Local Model of Growth-Induced Metabolic Decoupling in Tumors*,
> Journal of the Royal Society Interface (2026).

Figures 1 and 2 of the paper are schematics drawn in TikZ inside the manuscript source and
have no code here. Everything else is generated by the scripts in `code/`.

## What produces what

| Output | Where it appears | Run, in this order |
|---|---|---|
| `figures/shuttle_severing.pdf` | Figure 3 | `run_all.py` then `plot.py` |
| `figures/shuttle_operator.pdf` | Figure 4 | `full_solver.py` then `fold_from_measured.py` |
| `figures/shuttle_growing.pdf` | Figure 5 | `growing_run.py` then `plot_growing.py` |
| `figures/shuttle_fold.pdf` | ESM S1 | `plot_fold.py` |

`shuttle.py`, `reduced_fold.py` and `growing_run.py` are also imported as modules by the
plotting scripts, so they must sit alongside them.

The data-producing stages write `.npz` files into `code/`; the plotting stages read those and
write PDFs into `figures/`. Running a plotting script without its data stage will fail.

## Reproducing everything

```bash
cd code
python run_all.py            # Figure 3 data      (~2 min)
python plot.py               # Figure 3
python full_solver.py        # Figure 4 data      (~3 min)
python fold_from_measured.py # Figure 4
python growing_run.py        # Figure 5 data      (~10 min, the longest stage)
python plot_growing.py       # Figure 5
python plot_fold.py          # ESM S1 figure, self-contained (~2 min)
```

Or simply `make` from the repository root.

## Requirements

Python 3.11 or later, with `numpy`, `scipy` and `matplotlib`. No other dependencies, no
compilation, no GPU. Developed against numpy 2.x and scipy 1.18.

## Numbers the scripts print

Each stage prints the quantities quoted in the paper, so a reproduction can be checked
without opening the figures. The values obtained on a clean run are:

- Figure 3: oxidative shell mass 0.288 at `L=1.5` and 0.066 at `L=6`; static shuttle
  0.194 to 0.058 under dilution (a factor 0.30) against 0.163 to 0.171 when the supply is
  held; grid convergence 4.18e-4 relative between 300 and 600 cells.
- Figure 4: `alpha*` 0.0631 bistable against 0.0029 monostable; held exponent -0.532
  against the derived -1/2; diluting collapse slope 0.961 against unit slope; grid
  convergence 2.34e-3 between N=1200 and 2400.
- Figure 5: peak densities 76.7 and 58.2 coordinated against 7.9 and 7.2 decoupled;
  consumer-weighted oxidative activity 0.78 against 0.01.
- ESM S1 fold figure: `alpha*` 1.055; held exponent -0.550; diluting collapse slope 1.029.

## A caveat on the growing-domain solver

The threshold growth rate read from `growing_run.py` is sensitive to the mesh, and the
paper says so. Under proliferation-compensated supply the source is proportional to the
local density while the volume-filling factor limits only the aggregating velocities, so
nothing bounds the peak density and the cluster width ends up set by the mesh rather than by
cell diffusion. Refining from N=500 to 1000 to 2000 moves the measured threshold from about
0.075 to 0.058 to 0.045. Halving the time step changes nothing, so the sensitivity is
spatial. The qualitative behaviour — a threshold under held supply, none under dilution, and
a phenotype flip on decoupling — is unaffected at every resolution tested. Limiting
proliferation by the same packing factor restores grid convergence but shifts the operating
density, which would require recalibrating the remaining parameters; the shipped code is the
version the paper reports.

## Determinism

Everything here is deterministic: there are no random number draws in any stage, so a clean
run reproduces the published figures exactly on the same numpy and scipy versions.
